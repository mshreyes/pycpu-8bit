Welcome: What Is This Page?

A computer processor (CPU) looks complex, but it only does one simple job over and over: it reads a short command from memory, figures out what the command means, and does a basic math or data move. This simulator slows the CPU down so you can click a button and watch each step happen in plain sight.

1. The Dark Banner at the Top

At the top of the simulator is a dark box. Every time you click a button, this box explains what the CPU just did in one plain English sentence. If you only look at one thing, look here.

2. Left Panel: Program Instructions

This is the list of instructions you want the CPU to run (for example, MOVI R0, 14 means "put the number 14 into slot R0"). You can pick a pre-made example from the dropdown menu or type your own, then click Load into Memory.

3. Center Panel: Inside the CPU

Every instruction takes three small steps: Fetch (read the command from memory), Decode (understand the command), and Execute (do the math or move the number). You can watch the numbers inside the CPU's temporary slots (R0 to R3) change as it works.

4. Right Panel: Memory (RAM)

Memory is just a numbered grid of boxes (from box 0 to box 255). When you load a program, your instructions are turned into numbers and placed into these boxes starting at box 0. The blue box shows which instruction the CPU is reading right now.

How to Use the Control Buttons

Small Step (Fetch / Decode / Execute): Advances the CPU by just one-third of an instruction so you can see Fetch, Decode, and Execute separately.

Full Instruction: Runs Fetch, Decode, and Execute all at once to finish one whole line of your program.

The (i) Buttons: Hover over any i button to see a quick definition, or click it to open that term in the Wiki.

Wiki

Every part of the simulator is explained below in simple terms, with links to Wikipedia if you want to explore the deeper electronics.

CPU (Central Processing Unit)

The main chip in a computer that runs instructions. It does not think on its own; it simply follows a list of basic commands stored in memory one step at a time.

Read on Wikipedia →

Instruction Cycle (Fetch, Decode, Execute)

The three-step loop that every CPU repeats forever: grab the next command from memory (Fetch), figure out what it means (Decode), and do the work (Execute).

Read on Wikipedia →

1. Fetch

The CPU looks at the Program Counter (PC) to see which memory box holds the next command, copies those two boxes into the CPU, and moves the PC bookmark ahead by 2.

Read on Wikipedia →

2. Decode

Inside memory, commands are stored as plain numbers. During Decode, the CPU translates those numbers into a specific action (like Add or Move) and picks which registers to use.

Read on Wikipedia →

3. Execute

The CPU performs the decoded command—such as adding two numbers in the Math Unit (ALU), saving a number into a register, or printing a number to the screen.

Read on Wikipedia →

Registers (R0, R1, R2, R3)

Four small number slots built directly inside the CPU. Because they are inside the CPU, it can do math on them immediately. Each 8-bit slot can hold a whole number from 0 to 255.

Read on Wikipedia →

PC (Program Counter)

A bookmark that remembers the memory box number of the next instruction to run. Normally it counts up by 2 after each command, unless a Jump command sends it to a different box.

Read on Wikipedia →

IR (Instruction Register)

Holds the single command that the CPU is currently decoding and executing.

Read on Wikipedia →

MAR (Memory Address Register)

Holds the box number in Memory (RAM) that the CPU is currently reading from or writing to.

Read on Wikipedia →

SP (Stack Pointer)

Points to a temporary scratchpad area at the very end of memory (starting at box 255) used when calling functions with CALL and returning with RET.

Read on Wikipedia →

ALU (Arithmetic Logic Unit)

The calculator inside the CPU. It adds, subtracts, and compares numbers stored in the registers.

Read on Wikipedia →

Flags (Z and C)

Tiny indicator lights set by the calculator (ALU). Z (Zero) turns to 1 when a calculation equals 0. C (Carry) turns to 1 when an addition goes past 255. Jump commands check these lights to decide whether to loop.

Read on Wikipedia →

Memory (RAM)

A grid of 256 numbered boxes (0 to 255). Each box holds one number between 0 and 255. Both your program commands and your saved data live in these boxes.

Read on Wikipedia →

Assembly Language

Short text words like MOVI, ADD, and OUT that represent CPU commands. When you click "Load into Memory", the assembler translates these words into numbers for the CPU.

Read on Wikipedia →

Screen Output (OUT)

When your program runs OUT R0, the CPU sends the number currently inside slot R0 to the output box so you can see the answer.

Read on Wikipedia →

How This Simulator Works

This simulator models a classic Von Neumann computer written in Python and running directly in your browser using WebAssembly.

1. Every Command Uses Two Memory Boxes (2 Bytes)

To keep the CPU simple to follow, every line of assembly code is translated into exactly 2 numbers (2 bytes) in memory:

• First Box: Tells the CPU which command to run (for example, 2 means MOVI, 6 means ADD) and which register to use.
• Second Box: Holds the number or memory address you typed (from 0 to 255).

Because every command takes 2 boxes, the Program Counter (PC) always steps forward by 2 (`0`, `2`, `4`, `6`...).

Ben Eater's 8-Bit Breadboard Computer (SAP-1)

The register layout (PC, IR, MAR, R0–R3, ALU, and Flags) and step-by-step Fetch/Decode/Execute model are inspired by Ben Eater's Simple-As-Possible (SAP-1) 8-bit computer design.

Nand2Tetris (The Elements of Computing Systems)

Course and book by Noam Nisan and Shimon Schocken explaining how a minimal assembler translates human mnemonics and labels into binary machine instructions.

https://www.nand2tetris.org/ →

Marco Schweitzer's 8-Bit Assembler Simulator

Inspired the side-by-side workflow of assembling instructions directly into a visible 256-byte RAM grid.

https://schweigi.github.io/assembler-simulator/ →
